## 1. プロジェクト概要

### 1.1 目的
鎌倉インターナショナルFCのNFT保有者（オーナー）に対し、単なる所有を超えた「没入体験」を提供する専用ポータルサイトを構築する。
「スタジアムの一部を所有している」という実感を持たせ、KSP（ポイント）を通じたチームへの貢献を可視化することで、継続的なエンゲージメントを高める。

### 1.2 ターゲットユーザー
- **コアターゲット**: 鎌倉インテルNFT（「鳩スタ」草オーナー等）保有者
- **ユーザー心理**: チームを応援したい、所有している区画を確認したい、特典やステータスを感じたい。

## 2. デザイン・UI/UXガイドライン

既存のWebサイトおよび「Shoot Zone」の世界観を継承・拡張しつつ、最新技術とスタジアムの融合を限界まで突き詰めた表現で、圧倒的な没入感を演出する。
「かっこよさ」と「最先端感」を極限まで織り込み、単なるWebサイトの枠を超えた「圧倒的な未来」を感じさせる世界観を構築する。
世界トップレベルのデザイナーによる制作を想定し、妥協のないクオリティを目指す。

### 2.1 トーン＆マナー
- **コンセプト**: 「Beyond the Stadium - 限界突破した未来型コックピット」
- **カラーパレット**: 既存サイト（https://kamakura-stadium-nft.com/）の配色をベースにしつつ、ネオンや発光表現を強化。
  - **ベース**: ダークモード（Deep Space Black, Midnight Navy）
  - **アクセント**: 鎌倉インテルグリーン（Neon Green）、ゴールド（Cyber Gold）、白（Holographic White）
- **ビジュアルスタイル**:
  - **Future Tech & Organic**: デジタルなグリッドと、スタジアムの「芝」や「熱狂」という有機的な要素を高度に融合させる。
  - **Dynamic Immersion**: 静止画ではなく、微細なアニメーション、パララックス、WebGLを用いた3D表現などを駆使し、「生きている」インターフェースを作る。
  - **High-End UI**: 映画のSFインターフェースのような、緻密で機能美にあふれたデザイン。

### 2.2 既存資産の活用
- ヒーローイメージや背景には、既存サイトで使用されている高品質なスタジアム写真、選手画像、芝生のテクスチャを使用する。
- 「Shoot Zone」のような3D的、または俯瞰図的なマップ表現を取り入れ、自分の座席位置が視覚的にわかるようにする。

## 3. 機能要件

### 3.1 認証・ユーザー管理
- **ログイン**: メールアドレス（ID） ＋ 初期パスワード（運営発行）
  - 既存の高齢層ユーザーにも配慮し、Metamask等のウォレット接続は必須としない（将来的な拡張としてはあり）。
- **初回フロー**: ユーザーは運営から送付されたID/PASSでログインし、パスワードを変更する。
- **NFT紐付け**: バックエンドで「ユーザーID」と「保有NFT情報（区画番号、TokenID）」が紐付いていること。

### 3.2 ダッシュボード（マイページ）
ログイン後のホーム画面。
- **オーナーシップ表示**:
  -「あなたの座席（区画）」を表示（例: "Main Stand A-12"）。
  - 可能であればスタジアムマップ上で該当箇所をハイライト。
- **KSP（鎌倉サポートポイント）表示**:
  - **累計KSP**: 過去全ての獲得ポイント。
  - **シーズンKSP**: 今シーズンのランキング・表彰対象となるポイント。
  - **今節獲得KSP**: 直近のアクションで得たポイント。
  - **表現**: 数字だけでなく、円グラフやゲージを用いて直感的に表示。

### 3.3 コンテンツ・情報発信
- **限定動画**: 試合の裏側、ロッカールーム、特定アングルからの試合映像など（YouTube限定公開/Vimeo埋め込み）。
- **チームブログ**: noteの代替。WordPressの投稿機能を利用。「一般公開」と「ホルダー限定」の出し分け。
- **県リーグ情報**: 順位表、次節の対戦相手、試合日程。初期は管理画面からの手動更新とするが、リーグ公式サイト等からの自動取得（Webスクレイピング/API） を検討・実装し、運用負荷を軽減する。

### 3.4 ゲーミフィケーション（没入要素）
- **ミニゲーム（試合予想）**:
  - 次節のスコア予想、MOM（Man of the Match）予想。
  - 投票UIを設置。的中時にKSPを付与（管理者が手動または半自動で付与）。
- **所有者移転申請**:
  - NFTを二次流通で譲渡された場合、**移転を受けた側（新所有者）**が申請を行うフォーム。

### 3.5 管理者機能
- **ユーザー管理**: ユーザーの検索、登録、編集、削除。
- **一括操作**: CSVによるユーザー登録、NFT情報の紐付け更新、KSPの一括付与。

## 4. 非機能要件
- **モバイルファースト**: スタジアム現地（スマホ）での閲覧・操作を最優先する。
- **パフォーマンス**: 動画や画像が多くなるため、遅延読み込み（Lazy Load）等を徹底する。
- **拡張性**: 将来的にWeb3ウォレット接続（NFT自動認証）に移行できるDB設計にする。

---

## 5. システム基本設計（アーキテクチャ）

### 5.1 技術スタック
既存のWordPress環境を最大限活用し、コストと運用負荷を抑える構成とする。
- **Platform**: WordPress (Latest ver)
- **Theme**: 自作テーマ または 子テーマ（Existing Theme Child）
- **Frontend**:
  - PHP (WordPress Template Hierarchy)
  - JavaScript (Vanilla JS または Alpine.js/Vue.js を部分的に利用して動的UIを実現)
  - CSS (Tailwind CSS 推奨、または既存CSS)
- **Database**: MySQL (WordPress standard + Custom Tables)
- **Batch Processing**: WP-Cron（簡易タスク）、または外部スクリプト（データ取得用）

### 5.2 外部データ連携（Data Fetching）
- **League Data Scraper**:
  - **概要**: 神奈川県社会人サッカーリーグ等の公式サイトからHTMLを解析し、順位・試合結果・日程を抽出する。
  - **実装方式**: PHPライブラリ（Goutte/Symfony Panther）によるスクレイピング、またはPython等による外部バッチ処理。
  - **頻度**: 1日1回、または試合開催日に合わせた定期実行。

## 6. データベース設計

WordPress標準テーブルに加え、アプリケーション固有のデータを管理するカスタムテーブルを作成する。

### 6.1 テーブル定義

**wp_kmnft_user_meta (ユーザー拡張情報)**
標準の `wp_usermeta` でも代用可能だが、検索性を考慮し別テーブル、またはメタキー設計を明確にする。
- `user_id` (FK): WPユーザーID
- `wallet_address`: (Optional) 将来用
- `rank_current`: 現在の会員ランク

**wp_kmnft_holdings (NFT/区画所有情報)**
- `id`: PK
- `user_id`: 所有者のWPユーザーID
- `token_id`: NFTのトークンID
- `zone_code`: 区画コード（例: "MAIN-A-01"）
- `zone_name`: 表示名（例: "メインスタンド A列 1番"）
- `image_url`: 個別NFT画像のパス

**wp_kmnft_ksp_ledger (KSPポイント台帳)**
ポイントの増減履歴を全て記録する。
- `id`: PK
- `user_id`: 対象ユーザーID
- `amount`: ポイント数（正の数:付与、負の数:消費）
- `transaction_type`: 区分（LOGIN, GAME_WIN, EVENT_PARTICIPATION, ADJUSTMENT）
- `season`: シーズン年度（例: 2024）
- `description`: ユーザー向け履歴表示用テキスト
- `created_at`: 日時

**wp_kmnft_prediction_games (予想ゲーム)**
- `id`: PK
- `match_id`: 試合ID（別途試合管理が必要、または固定文字列）
- `user_id`: 投票ユーザー
- `prediction_score_home`: 予想スコア（自チーム）
- `prediction_score_away`: 予想スコア（敵チーム）
- `prediction_mom`: 予想MOM選手名
- `status`: 状態（PENDING, WON, LOST）
- `created_at`: 投票日時

## 7. サイトマップ・画面構成

- **LP / Top (既存サイト)**
  - 「ホルダーログイン」ボタンを配置
- **Login Page**
  - カスタムログイン画面（WPロゴではなくプロジェクトロゴを使用）
- **Dashboard (My Cockpit)**
  - KSPサマリー
  - 保有区画ビジュアル
  - 最新のお知らせ（ブログ新着）
  - 今週のミニゲームへのリンク
- **Contents / Media**
  - 限定動画一覧
  - コラム・ブログ記事詳細
- **Game / Interaction**
  - 試合予想投票フォーム
  - KSPランキング表
- **League Info**
  - 順位表・日程表（自動取得/手動更新）
- **Profile / Settings**
  - パスワード変更
  - 所有者移転申請フォーム
- **Admin Console (管理画面 - WP Admin内)**
  - **ユーザー管理一覧**:
    - ユーザー検索、フィルタリング（KSPランク別、保有ゾーン別）
    - 新規ユーザー登録、アカウント削除、強制パスワードリセット
  - **ユーザー詳細編集**:
    - 基本情報編集
    - 保有NFT（区画）の追加・削除・付替
    - KSPの手動付与・減算（補填対応など）
  - **一括インポート/エクスポート (Bulk Operations)**:
    - ユーザー一括登録/更新 (CSV): ID, Pass, Email, Initial_KSP
    - NFT所有権一括更新 (CSV): User_ID, Token_ID, Zone_Code（所有者移転の反映用）
    - KSP一括付与 (CSV): 試合結果やイベント参加者リストに基づいた一括ポイント付与

## 8. 開発フェーズ

### Phase 1 (MVP)
- ユーザーDB構築・管理者用CRUD機能（登録・編集・削除）
- CSVインポート/エクスポート機能（ユーザー・NFT紐付け・KSP）
- ログイン機能
- ダッシュボード（保有NFT表示、KSP累計表示のみ）
- ブログ機能移行

### Phase 2 (Interaction)
- KSP増減ロジック実装（ログインボーナス等）
- ミニゲーム（予想機能）実装
- ランキング表示
- リーグ情報自動取得機能（スクレイピングBot）の試験導入

### Phase 3 (Expansion)
- 動画コンテンツ拡充
- ウォレット接続
